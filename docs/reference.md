# momonga reference

Generated by `node scripts/reference.ts` from the tables of the product. Do not edit this file by hand: change the product and generate it again.

## Root options

```text
momonga [options] [prompt]
```

| Option | Meaning |
| --- | --- |
| `-V, --version` | output the version number |
| `-p, --print [prompt]` | run the prompt without a terminal UI and print the result; text piped on standard input is given to the run after the prompt, and is the prompt when -p has none |
| `--output-format <format>` | output format of --print and attach; values: `text`, `json`, `stream-json`; default: `"text"` |
| `--permission-mode <mode>` | permission mode of the session; values: `manual`, `acceptEdits`, `plan`, `auto`, `bypassPermissions` |
| `--model <model>` | the model of the session, for example devstral-small-2 (momonga models lists them; /model switches it in an interactive session) |
| `--effort <level>` | the reasoning effort the session asks of its model, sent only to a model that declares a reasoning control and moved to the nearest level it accepts (/effort changes it in an interactive session); values: `none`, `minimal`, `low`, `medium`, `high`, `xhigh` |
| `--dangerously-skip-permissions` | run in bypassPermissions mode |
| `--sandbox-network <setting>` | the network of a sandboxed command in this session: deny, ask or allow; wins over the setting sandboxNetwork; values: `deny`, `ask`, `allow` |
| `--skill <name>` | run the prompt with this skill activated |
| `--image <path>` | attach an image to the prompt; repeat for several (needs a model that declares image input) |
| `--until <command>` | a shell command that must exit 0 before the run counts as complete; repeat for several. The runtime runs it after the model stops, never the model, so it must only check and change nothing |
| `--require <text>` | a completion requirement that has no mechanical check; the report lists it as not run; repeat for several |
| `--mandate <name>` | run under the mandate of this name from the user settings (mandates): only what it allows is run, what it asks for is held for your approval while other work goes on, and its budget bounds the run |
| `--issue <address>` | run without a terminal UI to resolve an issue on a declared forge, given by its address as the forge shows it (https://\<host>/\<owner>/\<name>/issues/\<number>); needs --mandate; the run ends with a pull request that closes the issue and a comment on it |
| `--max-cost-usd <usd>` | the money limit of the run in US dollars; the run stops before a model request that would pass it |
| `--verbose` | print tool activity to stderr |
| `--resume [session-id]` | reopen a conversation of this folder by its id or a unique prefix of at least 8 characters; without an id, choose from a list |
| `--continue` | reopen the newest conversation of this folder |
| `--screen-reader` | draw the interactive session as plain appended lines for a screen reader |
| `-h, --help` | display help for the command |

## Commands

| Command | Meaning |
| --- | --- |
| `momonga attach [run-id]` | follow a run until it ends; the latest run of this directory when no id is given |
| `momonga approve [approval-id] [option]` | list pending approvals, show one, or resolve it with allow_once, allow_always, reject_once or reject_always |
| `momonga cancel [run-id]` | cancel a run; the running run of this directory when no id is given |
| `momonga report [run-id]` | show the verification report of a run: the declared completion conditions, what passed, failed or was not run, and the residual risk; the latest run of this directory when no id is given |
| `momonga trace [run-id]` | show the model and tool spans of a run; the latest run of this directory when no id is given |
| `momonga acp` | speak the Agent Client Protocol on standard input and output so an editor can drive momonga |
| `momonga update` | replace this executable with the latest release after verifying its checksum and signature |
| `momonga daemon` | manage the background daemon |
| `momonga daemon start` | start the daemon, or start a new one beside it when this program is newer |
| `momonga daemon status` | show whether the daemon runs, its version and the state of its processes |
| `momonga daemon stop` | stop the daemon and the work it runs, after a bounded wait for its processes to end |
| `momonga gateway` | inspect and tune the model gateway |
| `momonga gateway probe <model>` | measure a model of a managed server, an OpenAI-compatible server or an Ollama server and record the result for the gateway (an Ollama server: trained context length, tools, vision, thinking and model digest; a managed or OpenAI-compatible server: tool calling, structured output, stop sequences, parallel calls, reasoning control, usage) |
| `momonga elicit [input-id]` | list pending MCP input requests, show one, or answer it with --accept, --decline, --cancel or --responses |
| `momonga mcp` | inspect and authorize the MCP servers of this folder |
| `momonga mcp list` | list the MCP servers with their transport and authorization state |
| `momonga mcp login <server>` | authorize a remote MCP server in the browser |
| `momonga auth` | sign in to a subscription provider, sign out, and show the saved accounts |
| `momonga auth login [provider]` | sign in to a subscription provider in the browser |
| `momonga auth logout [account]` | sign out a saved account; without a terminal the account is required |
| `momonga auth status [model]` | show the saved accounts, their state, where to manage usage, and the model new sessions start with or the model named |
| `momonga auth resume <account>` | resume plan use of an account paused by a usage limit |
| `momonga auth reset-host` | register this computer as a new host; asks first, or needs --yes without a terminal |
| `momonga status [run-id]` | show a run, the subagent runs under it and the approvals waiting in them; the latest run of this directory when no id is given |
| `momonga jobs [session-id]` | list the background jobs of a session, including those of its subagents; the session of the latest run of this directory when no id is given |
| `momonga memory` | add, review and retire the memories of this folder and of all folders |
| `momonga memory add <text...>` | add a memory as a person; --path binds it to a file of this folder, so it shows as stale once the file changes |
| `momonga memory list` | list the memories |
| `momonga memory show <id>` | show a memory with its source |
| `momonga memory history <id>` | show a memory with the notes it replaced and the ones that replaced it, and their validity |
| `momonga memory delete <id>` | retire a memory: it is no longer recalled or listed and stays in momonga memory history |
| `momonga memory review` | list the memories the agent proposed in this folder and wait for your decision |
| `momonga memory review accept <id>` | accept a proposed memory, so later sessions recall it |
| `momonga memory review reject <id>` | reject a proposed memory, so it is never recalled and never proposed again |
| `momonga memory restore <id>` | bring an archived memory back |
| `momonga memory promote <id>` | write an accepted procedure memory as a skill |
| `momonga rule` | standing rules that bind every run of a folder or of all folders |
| `momonga rule add <target> <text...>` | add a rule; --deny or --ask makes it enforced by the permission system |
| `momonga rule list` | list the rules of this folder and the rules for every folder, enforced or text-only |
| `momonga rule retire <id>` | retire a rule; a retired rule stays in the history |
| `momonga rule history <id>` | show the rules a rule replaced and the ones that replaced it, with their validity |
| `momonga cost [run-id]` | show the model cost of a run, of a session, or of the sessions of this folder |
| `momonga reliability` | report the completion, recovery, duplicate, intervention, budget, time and cost indicators of the terminal tasks of the period |
| `momonga permissions` | review the permission decisions of recorded tool calls |
| `momonga permissions review [run]` | list a sample of recorded tool calls to review with the rates of the reviews stored so far, or store the review of one call |
| `momonga eval <dataset>` | run a golden dataset against the daemon and report the pass rates |
| `momonga eval context <dataset>` | run a context dataset live, each case in its own temporary home with its own daemon, or measure recorded transcripts with --replay, and report the metrics of Evidence-Based Context |
| `momonga eval yield <dataset>` | run a yield dataset live and judge whether reflection pays: each family runs a learn session and then a reuse session with and without the candidates of its reflection, counted as accepted when they hold an anchor of the dataset; exits non-zero when the gate fails |
| `momonga eval compare <baseline> <candidate>` | print the paired differences of two context reports and pass or fail the candidate against the gate |
| `momonga eval bench <directory>` | run every task of the benchmark in the directory on one model, each trial in a fresh copy of its repository, check each with the oracle of its task, and print the reliability report; with --validate, check the benchmark itself without a model |
| `momonga auto-mode` | measure how well a model judges approvals for auto mode, or show the stored measurement |
| `momonga auto-mode check [model]` | run the auto-mode dataset against a classifier model in temporary homes and store the measurement; auto mode stays selectable whatever it shows |
| `momonga auto-mode status [model]` | show the stored measurement of a classifier model for this version |
| `momonga context` | improve how the context is compacted, from the failures a benchmark shows |
| `momonga context improve` | analyse the scenarios that pass without compaction and fail with it, sample candidate guidelines for the compaction summary, benchmark each against the guideline in force, print the winner and its full text, and write the outcome to a file; nothing is stored |
| `momonga context guideline` | inspect, adopt and roll back the compaction guideline |
| `momonga context guideline adopt <outcome-file>` | store the winner of an outcome file that context improve wrote, after checking its digest and its parent and showing its full text |
| `momonga context guideline list` | list the adopted guidelines, oldest first |
| `momonga context guideline rollback <version>` | return to the text of an earlier version, recorded as a new version |
| `momonga secret` | store the secrets that model servers refer to |
| `momonga secret set <name>` | store a secret in the platform secret store; the value is read from the terminal |
| `momonga models` | list the configured models with the capabilities they declare |
| `momonga models detect [url...]` | ask the usual local addresses, and any address you name, what model server answers there; nothing is written |
| `momonga models check` | ask each configured server once whether it still lists its configured models, and list the models with the result |
| `momonga models catalog [account]` | list the models of a signed-in subscription account, read again from the provider; the active account when only one could answer |
| `momonga models add` | add a model of a model server found on this computer, of a server at an address, or of a signed-in subscription account |
| `momonga models remove [model]` | remove a model from the settings, with every setting that names it |
| `momonga models remove-server [server]` | remove a server and its models from the settings, with every setting that names them |
| `momonga models start [model]` | choose the model new sessions start with |
| `momonga models fallback` | the models tried in order when the model cannot answer |
| `momonga models fallback list` | list the fallback models in order |
| `momonga models fallback add [model]` | add a fallback model |
| `momonga models fallback remove [model]` | remove a fallback model |
| `momonga models fallback move [model]` | move a fallback model to another position |
| `momonga models billing` | the billing changes a request may make when it falls back |
| `momonga models billing list` | list the allowed billing changes |
| `momonga models billing allow [from] [to]` | allow requests to fall from one billing kind to another |
| `momonga models billing forbid [from] [to]` | no longer allow requests to fall from one billing kind to another |
| `momonga models role` | the model for summaries, reflection, analysis and the auto-mode classifier |
| `momonga models role list` | list the model of each job |
| `momonga models role set [job] [model]` | choose the model of a job: compaction, reflection, analysis or classifier |
| `momonga models role clear [job]` | let a job use the model of the session |
| `momonga models set [model] [field] [value]` | set a field of a model, for example capabilities.contextWindow |
| `momonga models unset [model] [field]` | clear a field of a model |
| `momonga models set-server [server] [field] [value]` | set a field of a server, for example billing |
| `momonga models unset-server [server] [field]` | clear a field of a server |
| `momonga models name [server] [name]` | name a server |
| `momonga models add-program` | declare a program that MomongaCode starts as a model server, and add the model it serves |
| `momonga models set-program [id] [field] [value]` | change the command, args, readyPath or modelFile of a declared program |
| `momonga models forget-program [id]` | forget a declared program that no server uses |
| `momonga models timeouts` | how long a request waits for the first reply and without any data, in whole minutes, 1 or more |
| `momonga models effort [level]` | the reasoning effort of the models that have none saved for themselves |
| `momonga models dialects` | the declared schema dialects |
| `momonga models dialects show` | print the declared schema dialects as JSON |
| `momonga models dialects set` | replace the declared schema dialects with the object of a JSON file |
| `momonga policy` | check the permission rules of this folder |
| `momonga policy verify` | prove that no allow rule gets around a deny rule, that no rule leaves a route to secrets, and that every rule can take effect; states what is proved and what is not |
| `momonga trust [folder]` | show whether a folder is trusted, with the settings of it waiting for approval, or decide it; the current folder when none is given |
| `momonga project-check` | the command that checks the work of the current folder, kept in the user settings (projectChecks) |
| `momonga project-check show` | print the check of the current folder |
| `momonga project-check set <command>` | make this command the check of the current folder |
| `momonga project-check clear` | remove the check of the current folder |

### Operations tools

| Tool | Meaning |
| --- | --- |
| `GitBranch` | Switches the working tree to a branch, creating it first when create is true. The result is checked against the branch that is actually checked out. |
| `GitStage` | Stages the given files for the next commit as they are in the working tree: a changed or new file is added, a deleted file is staged as deleted. Each path is read literally, relative to the working directory. The result is checked against the repository: nothing under the given paths may be left unstaged. A call whose paths match no change, staged or not, fails and stages nothing. |
| `GitCommit` | Commits the staged changes with the given message. The result is checked against the repository: the new head must have the previous head as its parent, the staged tree, and the message. A commit hook that changes the tree makes the call fail. |
| `GitFetch` | Fetches one branch from a remote into its remote-tracking branch. The checked-out branch and the working tree do not change; use GitUpdate to bring the checked-out branch up to the fetched commits. The result is checked against the remote: the remote-tracking branch must be at the commit the remote has. A remote written for SSH (git@host:path or ssh://) on a forge declared in settings is reached through the HTTPS place of that forge with the credential of the forge; the remote itself is not changed. A remote reached over SSH on no declared forge is not fetched from. |
| `GitUpdate` | Fast-forwards the checked-out branch to the fetched commits of a remote branch (run GitFetch first). It never creates a merge commit: when the checked-out branch and the remote branch have diverged the call fails and nothing changes. |
| `GitPush` | Pushes a local branch to the same-named branch of a remote. A branch that does not exist locally is not pushed. A plain push fails when the remote branch moved. With force the push is leased on the remote value observed before it, so a branch that moved is not overwritten. With delete the remote branch is removed. A force push, a delete and a push to a protected branch always need a person to approve. A pre-push hook of the repository runs first, on its own, without the network and without the credential; when it fails nothing is sent and its output is the result. A remote written for SSH (git@host:path or ssh://) on a forge declared in settings is reached through the HTTPS place of that forge with the credential of the forge, and the approval names that HTTPS URL; the remote itself is not changed. A remote reached over SSH on no declared forge is not pushed to. |
| `PullRequestComment` | Posts a comment on a pull request. The comment carries a hidden marker so that a call that was interrupted can be matched with the comment it posted. A posted comment cannot be taken back, so an interrupted call whose comment cannot be found is reported as unknown and not repeated. |
| `PullRequestCreate` | Opens a pull request from a pushed branch. Give issue when the pull request resolves an issue, so that the forge links them. The forge refuses a second open pull request for the same head and base, and a pull request that already exists at the given head commit completes the call without a request. |
| `PullRequestMerge` | Merges a pull request at the head commit that was approved. If the head moved since, nothing is sent and the call fails with the new head. Always needs a person to approve. |
| `PullRequestStatus` | Reads the state of a pull request: whether it is open or merged, its head commit, its URL, and every check of the head commit by name with its conclusion (a check that has not concluded shows its status). The comments of a pull request are read by PullRequestComments. |
| `PullRequestComments` | Reads the comments of a pull request: every review comment with its id, file and line (a comment whose line is no longer in the diff shows the file alone), and every conversation comment with its id, each followed by its text. The text is what people wrote on the forge. Nothing is changed. |
| `IssueRead` | Reads an issue: its number, title, state, author and text, and every comment on it with its id and author, each followed by its text. The text is what people wrote on the forge. Nothing is changed. |
| `IssueComment` | Posts a comment on an issue. The comment carries a hidden marker so that a call that was interrupted can be matched with the comment it posted. A posted comment cannot be taken back, so an interrupted call whose comment cannot be found is reported as unknown and not repeated. |

### Built-in agents

The `Agent` tool offers these subagents with no setup, before the agents of the files in `.momonga/agents`. An agent file with the same name replaces one; a file of a trusted folder replaces it only once you approve it.

| Agent | Meaning |
| --- | --- |
| `general-purpose` | A general subagent for work that needs its own context: researching a question across many files, carrying out several steps, or searching when it is not known where the answer is. Use it to keep that material out of this session; it returns only its result. |
